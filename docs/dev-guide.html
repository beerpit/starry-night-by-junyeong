1개요와 기획

1.1 배경

초등학교 2학년 아이가 미술학원에서 반 고흐의 「별이 빛나는 밤」을 얇은 타원형 팔레트 모양 나무판에 유화로 그려 왔다. 이 작품을 소재로, 데스크톱과 모바일에서 똑같이 돌아가는 웹 퍼즐 게임을 만들어 아이에게 선물한다.

1.2 기획 의도와 핵심 결정

🎨 작품을 그대로 존중한다

사진을 네모로 자르지 않고 팔레트 윤곽과 엄지 구멍, 오른쪽 홈까지 그대로 오려 낸 모양이 퍼즐 판이 된다. 조각도 팔레트 가장자리를 따라 잘린다. 완성하면 아이가 그린 별과 달이 실제 위치에서 반짝인다.

🧒 8살이 혼자 할 수 있게

글을 읽지 않아도 아이콘으로 이해되는 도구 막대, 큰 터치 영역(최소 40px 안팎), 넉넉한 스냅 허용 오차, 「딸깍·반짝」 즉각 피드백, 실패 없는 규칙(틀리면 그냥 놓일 뿐).

📈 오래 놀 수 있게

6단계 난이도(6→125조각), 회전 모드, 제한된 찬스와 별점(★1~3), 최고 기록, 스티커 7종으로 반복 플레이 동기를 준다.

🌐 어디서나, 무료로

설치·서버·빌드 없이 정적 파일만으로 동작한다. 브라우저만 있으면 Windows·macOS·Linux·Android·iOS·iPadOS 가 같은 코드로 돈다. 한 번 열면 오프라인(PWA)도 된다.

1.3 대상 사용자

사용자특징설계 반영
주 사용자: 초2 아이 (8세)터치 위주, 긴 글 싫어함, 성취감에 민감아이콘 중심 UI, 즉각적 소리·반짝임, 별점·스티커, 1~3단계 추천
동생·친구 (5~7세)정밀 조작 어려움6조각 「새싹」, 큰 스냅 허용 오차(칸의 20%), 밑그림 기본 켬
부모·가족함께 하거나 고난도 도전66·125조각, 회전 모드, 태블릿 가로 배치, 키보드 단축키

2.2 상황별 시나리오

A. 저녁, 아이 혼자 iPad

홈 화면 아이콘으로 실행 → 「🌙 달빛」 선택 → 밑그림을 보며 테두리부터. 한 조각이 안 보여 찬스 1번 → 완성, ★★, 「첫 완성」 스티커. 결과 창의 「다음: 🌀 소용돌이」.

B. 이동 중, 엄마 휴대폰

세로 화면: 판이 위, 조각이 아래. 두 손가락으로 확대해서 맞추다 목적지 도착 → 화면을 끔. 집에서 다시 열면 「▶ 이어 하기 · 🌀 소용돌이 · 14/35」.

C. 주말, 가족이 PC

「🎨 고흐 마스터」 + 회전 모드. 🧹 정리로 테두리 조각을 모으고, 오른쪽 클릭으로 돌리고, 덩어리를 만들어 판에 한 번에 넣는다. 원본 창은 모니터 구석에 크게 띄워 둔다(위치 기억).

분류목표방법

4.4 UI 구성 요소

요소설계
도구 막대항상 한 줄. 폭 1080px 이하 → 글씨 숨기고 아이콘만, 640px 이하 → 자주 안 쓰는 소리·도움말·전체 화면을 「⋯」 메뉴로, 단추 폭 36→33→31px 단계 축소, 345px 이하에선 시간 숨김. 그래도 넘치면 가로 스크롤(스크롤바 숨김). 진행률은 막대 아래 3px 선에 합쳐 줄을 늘리지 않음.
떠 있는 창원본·도움말: 제목 막대 끌기 이동, 오른쪽 아래 모서리 크기 조절, 닫기 전 위치·크기를 영속 저장(다시 열기·재시작 후 복원), 화면 밖으로 사라지지 않게 보정, 우상단 빨간 ✕, 모든 창 같은 제목 글꼴·닫기 단추.
모달확인(새로 시작?)·완성 결과처럼 메시지 성격만. Esc·✕·바깥 누르기로 닫힘.
목록 조작난이도 카드 = 라디오 그룹: ←→↑↓(격자 열 수 인식), Home/End, PgUp/PgDn, Enter. 「⋯」 메뉴: ↑↓ Home End Esc.
입력칸「그린 사람」: 운영체제 기본 선택·복사·붙여넣기 그대로, 게임 단축키는 입력칸에서 무시.
스크롤부드러운 스크롤 사용 안 함(문서 포함). 게임 화면은 고정 배치라 페이지 스크롤 없음.

7.1 사진에서 팔레트 모양 오려 내기 (tools/prep.html)

원본은 회색 리넨 천 위에 놓인 팔레트 사진(4000×3000)이다. 배경을 투명하게 만들어야 판 모양 퍼즐이 된다. 사람 손으로 윤곽을 따지 않고 색 기반 플러드필로 자동 추출한다.

  1. 배경 판정: 1000×750 으로 줄여 픽셀마다 판정. 리넨은 「채도 낮고 밝기 중간인 보랏빛 회색」, 받침대 그늘은 「갈색·어두운 무채색」. 실측 샘플: 리넨 (189,185,193) 채도 8, 그늘 (164,160,185) 채도 25, 달무리 (196,201,177) 채도 24 ← 배경과 비슷하지만 노란 기(파랑<빨강)로 구별.
  2. 가장자리 + 엄지 구멍 씨앗에서 플러드필 → 바깥과 구멍이 배경.
  3. 가장 큰 연결 성분만 남기고, 열림 연산(원형 커널 r=9 침식→팽창)으로 받침대 실밥·나무 옆면 같은 가는 돌기 제거.
  4. 안쪽 구멍 채우기: 바깥·엄지 구멍과 이어지지 않은 0 영역(흰 붓질을 배경으로 오인한 곳)은 그림으로 되돌림.
  5. 부드러운 윤곽: 마스크를 출력 크기(2000px)로 키우며 블러 → α' = clamp((α−0.5)·4+0.5) 로 1~2px 안티에일리어싱 가장자리.
  6. 원본을 경계 상자로 잘라 알파 적용 → PNG → cwebp -q 86 -alpha_q 100 (365KB) → 데이터 URL JS.
function bgLike(r, g, b) {
  const mx = Math.max(r, g, b), mn = Math.min(r, g, b);
  if (mx - mn < 18 && mx > 70 && mx < 236) return true;              // 무채색 리넨
  if (b >= r && mx - mn < 27 && mx > 130 && mx < 225) return true;  // 그늘진 보랏빛 회색
  if (r > b + 6 && mx > 50 && mx < 175 && mx - mn < 48) return true;  // 갈색 나무 옆면·받침대
  return (mx - mn < 12 && mx > 38 && mx <= 70 && r >= b - 2);       // 어두운 무채색 틈
}
왜 데이터 URL 인가? 파일로 열면(file://) 크롬은 같은 폴더 이미지도 「다른 출처」로 보아 getImageData 가 막힌다(캔버스 오염). 맞힘 판정·마스크 계산에 픽셀이 필요하므로, 그림을 스크립트 안의 데이터 URL 로 실어 어떤 실행 방식에서도 같은 출처가 되게 했다.

7.2 직소 탭 곡선

격자의 각 안쪽 변마다 3개의 3차 베지어로 된 탭 곡선을 만든다(Draradech 의 jigsaw 생성식을 변형). 변 A→B 의 진행 방향 비율 l, 수직 방향 오프셋 w(칸의 짧은 변 S 기준)로 제어점을 둔다. t=탭 크기(0.082~0.098), a…e=±0.025 흔들림, flip=±1(볼록/오목)은 시드 난수.

P(l, w) = A + û·l·L + n̂·w·S·flip          // û: A→B 단위벡터, n̂: 수직
p0=P(0,0)  p1=P(.2,a)  p2=P(.5+(b+d)k, −t+c)  p3=P(.5+(−t+b)k, t+c)
p4=P(.5+(−2t+b−d)k, 3t+c)  p5=P(.5+(2t+b−d)k, 3t+c)  p6=P(.5+(t+b)k, t+c)
p7=P(.5+(b+d)k, −t+c)  p8=P(.8,e)  p9=P(1,0)          // k = S/L (직사각형 칸 보정)
곡선 = C(p0,p1,p2,p3) + C(p3,p4,p5,p6) + C(p6,p7,p8,p9) → 34점 폴리라인
  • 변은 한 번만 만들고, 이웃한 두 칸이 같은 점열을 정방향/역방향으로 공유 → 이음새가 수학적으로 정확히 맞물린다.
  • 칸 다각형 = 위(정) + 오른쪽(정) + 아래(역) + 왼쪽(역). 그림의 바깥 테두리 변은 직선.
  • 탭 깊이 ≤ 0.31S, 탭 폭 범위 0.26~0.74 → 이웃 변의 탭과 겹치지 않는다.

7.3 빈 귀퉁이 제거와 자투리 병합

팔레트가 타원이라 네모 격자의 귀퉁이 칸은 그림이 거의 없다. 칸마다 덮임 비율(알파 평균)을 적분 영상(summed-area table)으로 O(1)에 구한다.

cov(칸) = Σα / 넓이   (500px 폭 알파 적분 영상, 사각형 합 = I(x1,y1) − I(x0,y1) − I(x1,y0) + I(x0,y0))
cov < 0.4%  → 조각 없음
cov < 32%   → 덮임 작은 순서로, 이웃 중 「맞닿은 변이 실제로 보이고(변 위 알파 평균×10) + 덮임이 큰」 묶음에 합침 (union-find)

합쳐진 조각의 윤곽은 칸 다각형들을 한 Path2D 에 같은 방향으로 넣어 nonzero 채우기 규칙으로 합집합을 얻는다(공유 변은 서로 상쇄 없이 덮임). 결과: 15×10=150칸 → 125조각, 3×2 → 6조각.

7.4 조각 스프라이트 굽기 (입체 테두리 + 그림자)

  1. base: 조각 경로로 clip → 그림을 그린다(팔레트 밖은 원래 투명이라 가장자리 조각은 자연히 팔레트 윤곽을 따름).
  2. 빛 테두리: 임시 캔버스에 base 실루엣을 흰색으로 채우고(source-in), base 를 (+k,+k) 밀어 destination-out → 왼쪽 위 가장자리 띠만 남음 → 42% 로 덧그림. 같은 방법으로 (−k,−k) 검은 띠 = 오른쪽 아래 그늘.
  3. 그림자: 여백(pad)을 둔 최종 캔버스에 shadowBlur 로 base 를 그려 그림자를 구워 넣음 → 매 프레임 그림자 계산 0.
  4. 맞힘 알파: base 를 1/4 로 줄여 알파만 Uint8Array 로 보관.

ctx.filter(blur) 는 사파리가 지원하지 않아 쓰지 않았다. 그림자·합성 연산은 모든 엔진 공통.

7.5 맞힘 판정 (투명한 탭 틈은 통과)

function hitPiece(p, wx, wy) {
  let [dx, dy] = rot90(wx - p.x, wy - p.y, -p.rot);   // 조각 회전을 되돌림
  const lx = dx + p.bw / 2, ly = dy + p.bh / 2;
  if (lx < 0 || ly < 0 || lx >= p.bw || ly >= p.bh) return false;
  return p.hit.a[(ly / 4 | 0) * p.hit.aw + (lx / 4 | 0)] > 70;      // 보이는 픽셀만
}

위(z가 큰) 조각부터 검사하므로, 탭 사이 투명한 틈을 누르면 그 아래 조각이 잡힌다. 사각 경계 상자 판정이었다면 엉뚱한 조각이 잡혔을 것이다.

7.6 스냅과 덩어리 결합

모든 조각은 제자리 중심 (hx, hy) 를 안다. 조각 p 와 이웃 q 가 같은 회전 r 일 때 「맞게 붙었다면 q 가 있어야 할 곳」은:

expected(q) = p.pos + R(r) · (q.home − p.home)        // R(r): 90°×r 회전
|q.pos − expected(q)| < tol  →  p 의 덩어리를 (q.pos − expected) 만큼 옮겨 붙이고 q 의 덩어리로 합침
tol = max(0.2·S, 16px / 확대배율)
  1. 놓은 덩어리가 회전 0이고 |pos − home| < tol 이면 → 판에 고정(전 조각을 고정 레이어에 찍고 목록에서 제거).
  2. 아니면 덩어리의 모든 조각 × 모든 이웃을 검사해 하나라도 맞으면 결합 → 반복(연쇄 결합, 최대 50회). 결합 뒤 다시 1을 검사.
  3. 회전: 덩어리 전체를 탭한 조각 중심 기준으로 pos' = pivot + R(1)(pos − pivot), rot' = rot+1.

7.7 카메라와 제스처

화면 = 월드 × s + o            월드 = (화면 − o) / s
핀치: 시작 때의 두 손가락 중점 m₀ 아래 월드 점 w 를 지금 중점 m 에 고정
      s = s₀ · d/d₀,  o = m − w·s
휠:   ctrl(트랙패드 핀치) 또는 「정수 deltaY ≥ 40 · deltaX = 0 · deltaMode≠0」(마우스 휠) → 커서 기준 확대
      그 밖(트랙패드 두 손가락 스크롤) → 이동
  • 첫 손가락이 조각에 닿았어도 움직이기 전에 두 번째 손가락이 오면 끌기를 취소하고 핀치로 전환.
  • clampCam: 내용 경계가 화면 가장자리 80px 안에 늘 남도록 → 「길을 잃은 화면」 방지.
  • 창 크기 변화(휴대폰 회전·주소창): 화면 중앙의 월드 점과 「맞춤 배율 대비 확대 비율」을 유지.

7.8 탁자 배치 (흩기·정리)

조각을 둘 「쟁반」 후보 배치를 만들고, 현재 화면 비율에서 가장 크게 보이는(맞춤 배율 최대) 후보를 고른다.

후보모양잘 맞는 화면
A 아래판 아래로 줄줄이휴대폰 세로
B 양옆판 왼쪽·오른쪽 기둥가로 화면, 조각 적음
C 사방 (k=1…12)양옆 k열 + 남는 조각은 아래태블릿·데스크톱, 조각 많음

칸 크기는 흩기 때 칸×1.22(탭이 살짝 겹침), 정리 때 칸×1.42(탭까지 다 보임). 칸은 판 중심에서 가까운 순으로 정렬해, 정리 때 테두리 조각이 판 가까이 오게 한다. 흩기는 시드 난수로 섞고 칸의 ±11% 흔들림.

7.10 완성 축하 연출 (fx.js)

  • 그림 속 별 반짝임: 잘라 낸 그림 기준으로 측정한 별·달 7곳 좌표(비율)에 방사형 그라디언트 + 회전하는 8갈래 빛살, 0.18초 간격으로 차례로 「팡」(easeOutBack) 후 맥박. 카메라를 따라가도록 매 프레임 그림 화면 사각형을 다시 구함.
  • 빛줄기: 오프스크린 캔버스에 그림(알파=팔레트 모양)을 그리고 source-in 으로 사선 그라디언트를 채워 lighter 합성 → 팔레트 모양 안에서만 빛이 지나감(3.2초 주기).
  • 입자: 별·종이 꽃가루(중력·공기저항·회전), 4.2초 동안 불꽃 원형 폭발. prefers-reduced-motion 이면 꽃가루를 줄이고 불꽃 생략.
  • 소리: C-E-G-C 팡파르 + 코드 진행 + 반짝 종소리(합성).

7.11 저장과 복원

조각을 놓을 때·찬스·회전·정리 뒤 400ms 디바운스로 저장, 탭 숨김(visibilitychange)·pagehide 때 즉시 저장. 복원은 같은 시드로 퍼즐을 다시 생성 → 저장된 위치·회전·덩어리·고정 여부·z 순서를 덮어쓴다. 고정 조각은 고정 레이어에 다시 찍는다. 조각 수가 다르면(버전 차이) 저장본을 무시한다.

시간은 250ms 틱마다 「게임 화면 · 첫 조작 이후 · 문서가 보임 · 틱 간격 < 5초」일 때만 더한다(백그라운드·절전 복귀 때 시간이 튀지 않음).

8.2 WebKit (iPadOS Safari) — ?selftest

사파리는 원격 자동화가 어려워, 게임에 ?selftest=단계[&rotate] 로만 켜지는 점검 스크립트를 넣었다. 실제 PointerEvent 를 캔버스에 보내 찬스 1회 + 끌기로 끝까지 풀고 결과를 화면에 띄운다. iPad Air 11 (M4) iPadOS 27 시뮬레이터(창 없이 부팅)에서 3단계·4단계 회전 모드 전 항목 통과.

8.4 화면 모음

9배포 (무료 호스팅)

서버 코드가 없으므로 game/ 폴더를 그대로 아무 정적 호스팅에 올리면 된다. 모두 HTTPS 를 기본 제공해 Service Worker(오프라인)·홈 화면 설치가 동작한다.

GitHub Pages

  1. 저장소에 game/ 포함해 push
  2. Settings → Pages → Source: GitHub Actions
  3. 저장소의 .github/workflows/pages.yml 예시(README 참고)로 game/ 업로드
  4. https://계정.github.io/저장소/

Cloudflare Pages

  1. Pages → 저장소 연결
  2. 빌드 명령: 없음, 출력 폴더: game
  3. 무료: 요청 무제한, 전 세계 CDN

Netlify

  1. Add new site → Deploy manually
  2. game 폴더를 끌어다 놓기
  3. 무료: 월 100GB 전송
새 판을 올릴 때: sw.js 의 VERSION 을 올린다(예: sn-v1.0.1). 「네트워크 우선」 전략이라 온라인이면 새 파일을 바로 받지만, 오래된 캐시를 정리하려면 버전을 바꿔야 한다.

로컬 실행

# 1) 파일로: game/index.html 더블클릭 (오프라인 SW 만 빠짐)
# 2) 로컬 서버로 (의존성 없음)
node tools/serve.mjs game 8080    # → http://127.0.0.1:8080/
