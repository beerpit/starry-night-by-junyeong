1기획

배경과 목표

아이가 미술학원에서 선생님 도움을 받아 얇은 타원형 팔레트 모양 나무판에 유화로 「별이 빛나는 밤」을 그려 왔다. 이 작품을 아이가 직접 가지고 놀 수 있는 게임으로 돌려주어, “내 그림이 게임이 됐다”는 자부심과 함께 원작 감상까지 이어지게 하는 것이 목표다.

디자인 원칙

① 아이 그림이 주인공

사각형으로 잘라 내지 않고 팔레트 윤곽·엄지 구멍·손잡이 홈까지 그대로 판으로 쓴다. 완성 순간 원본이 드러나며 그림 속 별이 실제로 반짝인다.

② 실패 없는 즐거움

벌점·시간 제한이 없다. 틀린 자리는 그냥 놓일 뿐. 막히면 미리보기·밑그림·정리·찬스로 스스로 해결한다.

③ 어느 기기나 똑같이

휴대폰 세로·가로, 태블릿, 데스크톱 모두 같은 규칙과 품질. 설치 없이 주소 하나로, 인터넷이 끊겨도.

④ 가족 친화

개인 정보는 기기 밖으로 나가지 않는다. 광고·결제·로그인 없음. 완성 카드로 기록을 남기고 나눈다.

2시나리오

대표 사용 이야기

S1. 첫 만남 (태블릿)

아이가 부모가 홈 화면에 추가해 둔 아이콘을 누른다 → 자기 그림이 둥실 떠 있는 시작 화면 → 「반짝반짝」 카드 → 12조각을 끌어 맞추며 「착!」 소리 → 4분의 1, 절반 알림 → 완성 불꽃과 ★★★ → 「다음 단계」.

S2. 막혔을 때 (휴대폰)

「초승달」 30조각 중 하늘 조각이 헷갈린다 → 미리보기 창을 띄워 옆에 두고 → 그래도 모르면 금색 찬스 단추 → 조각이 별가루 꼬리를 남기며 날아가 자리를 보여 준다 → 연속 5개를 빠르게 맞춰 찬스를 되찾는다.

S3. 나눠서 하기

저녁 먹으라는 말에 「처음」을 누르거나 앱을 닫는다 → 다음 날 카드에 「이어하기 41/66 · 12:30」 → 누르면 조각 위치·시간·찬스까지 그대로.

S4. 가족 도전 (데스크톱)

아빠와 「고흐의 밤」 173조각을 조각 돌리기 모드로 → 정리 단추로 테두리 조각과 어두운 나무 조각을 모으고 휠로 확대 → 완성 카드(PNG)를 저장해 할머니께 보낸다.

8.1 사진 → 팔레트 오려내기 (tools/prepare_image.py)

원본은 회색 천 위에 놓인 팔레트 사진이다. 배경 제거 AI 대신, 이 사진의 색 특성을 이용한 규칙 + 형태학(모폴로지)으로 재현 가능하게 처리했다.

  • 함정 1 — 달이 지워짐: 달 안쪽의 연한 크림색이 저채도라 「구멍」으로 오인됐다 → 구멍은 배경색과의 색 거리 최소 덩어리 하나만 고르도록 바꿈.
  • 함정 2 — 받침대·나무 단면 남음: 어두운 회색(밝기 88)·갈색 → 밝기 하한을 낮추고 「붉은 기 > 푸른 기 + 저채도」 갈색 조건을 추가, 원판 구조 요소 열기로 가는 돌출 제거.
  • 푸른 물감은 b−r 이 크고 검은 나무는 밝기 < 70 이라 배경과 섞이지 않는다. 흰 붓터치(푸른 기 있음)는 가장자리와 이어지지 않으므로 연결 성분 조건으로 보호된다.

8.2 직소 이음매 생성 (jigsaw.js)

① cols×rows 격자의 안쪽 꼭짓점을 칸 크기의 ±8% 흔든다. ② 이웃한 두 칸이 모두 그림을 덮으면 그 사이 이음매에 꼭지를, 아니면 직선을 둔다. ③ 이음매는 한 번만 만들고 양쪽 칸이 공유(한쪽은 정방향, 다른 쪽은 점 순서를 뒤집어 역방향)하므로 틈·겹침이 수학적으로 0이다.

// 이음매 방향 l(0~1)·법선 w 좌표(이음매 길이 단위). flip 으로 꼭지 방향 무작위
const t = 0.085 + rnd() * 0.03;              // 꼭지 크기
const j = () => (rnd() * 2 - 1) * 0.035;      // 모양 흔들기 A~E
return [P(0,0),
  P(0.2,A), P(0.5+B+D, -t+C), P(0.5-t+B, t+C),            // 목 → 머리 왼쪽
  P(0.5-2*t+B-D, 3*t+C), P(0.5+2*t+B-D, 3*t+C), P(0.5+t+B, t+C), // 머리
  P(0.5+B+D, -t+C), P(0.8,E), P(1,0)];                    // 목 → 끝
// 칸 윤곽 = 위(→) + 오른쪽(↓) + 아래(← 뒤집기) + 왼쪽(↑ 뒤집기): 모든 칸이 시계 방향
//  → 여러 칸을 한 Path2D 에 넣어도 nonzero 규칙으로 깔끔한 합집합

8.3 라벨링 — 어느 칸의 그림인가

저해상도 마스크(그림 4px = 1칸, 450×301)의 그림 칸마다 중심점이 어느 칸 경로 안에 있는지 isPointInPath 로 판정한다. 꼭지는 이웃 칸까지만 튀어나오므로 후보는 3×3 이웃뿐이다.

  • 안전 영역 지름길: 꼭지 최대 돌출(이음매 길이 × (2.5t + C) ≤ 0.32)보다 안쪽(0.36)에 있는 점은 판정 없이 바로 그 칸 → 판정 호출이 크게 줄어 6단계도 0.3~0.9초.
  • 24ms 마다 requestAnimationFrame 으로 양보 → 로딩 막대가 멈추지 않는다.
  • getImageData 를 전혀 쓰지 않으므로 file:// 로 열어 캔버스가 「오염」돼도 동작한다.

8.4 연결 성분과 작은 파편 병합

  1. 같은 칸 라벨끼리 4-이웃으로 묶어 파편을 만든다(엄지 구멍·손잡이 홈 때문에 한 칸이 둘로 끊어질 수 있음).
  2. 파편 쌍마다 맞닿은 경계 길이를 센다.
  3. union-find 로, 넓이가 칸 넓이 × 0.3 보다 작은 묶음 중 가장 작은 것부터 경계를 가장 길게 맞댄 이웃에 합친다(긴 경계 = 자연스러운 모양). 반복.
  4. 이웃 없는 아주 작은 섬(기준의 15% 미만)은 버린다 — 완성 때 원본이 덮는다.
  5. 조각 번호는 (행, x) 순으로 정해 시드가 같으면 어느 기기에서나 같은 조각.
for (;;) {
  adj = 묶음 사이 경계 길이 합(border 맵을 find() 로 접어서);
  small = 넓이 < minArea 이고 이웃 있는 묶음 중 가장 작은 것;
  if (small < 0) break;
  best = adj[small] 에서 경계 길이 최대(동률이면 번호 작은 쪽);
  parent[small] = best;  area[best] += area[small];
}

검증: 6단계에서 조각 넓이 합 / 그림 넓이 = 1.0000(빈틈·중복 없음), 최소 조각 ≥ 중앙값의 25%.

8.5 조각 굽기 (pieces.js)

  1. 오리기: 조각 경계 상자 + 여백 크기 캔버스에 clip(조각 경로) 후 그림의 그 부분만 drawImage.
  2. 영역 마스크: 조각 영역(마스크 해상도, 1칸 팽창)을 흰 캔버스로 만들어 destination-in — 같은 칸이 구멍으로 둘로 나뉜 경우 다른 쪽을 지운다. 팔레트 윤곽은 그림의 알파가 그대로 만든다.
  3. 입체 테두리: 실루엣에서 (d,d) 어긋난 실루엣을 destination-out 하면 왼쪽 위 가장자리만 남는다 → 흰색 50% 로 source-atop. 반대 방향은 남색 55% 그늘. 임의 모양(팔레트 곡선 포함)에 일정한 두께로 작동.
  4. 그림자판: shadowBlur 로 한 번 구운 그림자 + 8방향 1.3px 밝은 외곽선(검은 나무 조각이 어두운 탁자에서도 보이게).

결과적으로 매 프레임 조각 하나당 drawImage 한 번. 맞춘 조각은 판 크기 캔버스 한 장에 찍고 그림자판은 메모리에서 해제한다.

8.6 히트 테스트

_hitPiece(p, wx, wy) {
  (dx,dy) = (wx,wy) − 조각 중심;  회전이 있으면 −rot 만큼 되돌림;
  (bx,by) = 제자리 기준 그림 좌표;
  if (!영역마스크[by/4][bx/4]) return false;      // 빠른 거절(구멍·다른 파편)
  return hit.isPointInPath(p.path, bx, by);       // 정확한 이음매
}
hitTest: 맨 위 조각부터 → 실패하고 손가락이면 반경 18px(화면) 12점 링에서 다시, 가장 위 조각

8.7 탁자 배치

필요한 빈 넓이 A = max(Σ조각 상자 넓이 × 0.95, 조각 수 × 큰 조각(상위 25%) 자리 × 0.82). 두 후보를 계산해 판이 화면에 더 크게 보이는 쪽을 고른다.

  • side: 탁자 높이 = 판 + 여백, 너비 = 판 + A/높이 → 화면 비율에 맞게 늘림.
  • bottom: 탁자 너비 = 판 + 여백, 높이 = 판 + A/너비 → 화면 비율에 맞게 늘림.
  • 탁자에서 판(+여백)을 뺀 왼·오른·위·아래 네 사각형에 격자 자리를 만들고(자리 부족 시 0.06씩 촘촘히, 최대 0.4배), 판에 가까운 자리부터 고른 뒤 읽는 순서로 정렬.
  • 정리: 테두리 조각 먼저, 그다음 밝기(16px 격자 평균) 오름차순 → 검은 나무·짙은 하늘·밝은 구름이 모인다.
  • 화면을 돌려 배치 방식이 바뀌거나 탁자 밖 조각이 생기면 흩어진 조각만 0.4초 애니메이션으로 재정리.

8.9 렌더 루프

필요할 때만 그린다: 상태가 바뀌면 requestRender() 가 rAF 를 한 번 예약. 트윈·입자·끌기·핀치·찬스 비행·원본 드러내기 중에는 다음 프레임을 계속 예약하고, 모두 끝나면 멈춘다 → 가만히 있으면 CPU·배터리 사용 0.

8.10 저장·재개

  • 조각 모양은 저장하지 않는다. 시드(32비트) + 단계로 같은 조각을 다시 만들고(mulberry32 난수 + 결정적 순서), 위치·회전·맞춤 여부·쌓인 순서만 저장(수 KB).
  • 저장 시점: 놓기·정리·찬스·밑그림 변경 후 0.4초 디바운스, 화면 숨김(visibilitychange)·pagehide 즉시.
  • 형식 번호·조각 수·시드가 다르면 저장을 버리고 새로 시작(안전). 다른 기기 크기로 열어 탁자 밖에 놓인 조각은 자동 정리.

8.11 축하 효과 (fx.js)

  • 원본 드러내기 1.1초(맞춘 층 위에 그림 알파 0→1, 이음매·테두리 사라짐).
  • 그림 속 실제 별 위치(손으로 지정한 별·달 8개 + 자동 검출한 마을 창문 6개)에서 0.28초 간격 불꽃 12발 — 중력·감쇠 입자, lighter 합성.
  • 달 주위 소용돌이 90입자(나선: 각속도·반지름 증가), 화면 좌표 색종이(흔들림·뒤집힘), 이후 별·창문 방사형 반짝임이 계속.
  • prefers-reduced-motion 이면 입자 수를 1/4 로, 색종이 생략.

  • 소리: 헤드리스는 무음 실행 — 실제 음색·크기는 미확인.
  • 완성 카드 공유 시트(모바일 navigator.share)와 저사양 기기 성능.
